## P1：启动体验与托盘解锁会话

### P1.1 消除伴生控制台

主要文件：src-tauri/src/main.rs、scripts/Start-LimeDesktop.ps1、scripts/Test-LimeLifecycle.ps1、README。

1. 复核 EXE 构建类型及 PE 子系统，区分应用自己的控制台和用户主动打开的 PowerShell。当前属性只在非 debug 构建启用 GUI 子系统，脚本已有 Hidden。
2. 建议 Windows 桌面入口统一使用下面的属性，让日常 debug EXE 也不创建控制台；非 Windows 不受影响：

```rust
#![cfg_attr(target_os = "windows", windows_subsystem = "windows")]
```

3. 检查诊断能力。构建输出仍在构建终端；如需运行日志，仅记录固定阶段、错误类别与必要运行信息，禁止记录 IPC 参数、主密码、账号或解密内容。不为这一问题引入大型框架。
4. 启动脚本增加明确 Debug/Release 选择，兼容原有默认调用。路径从脚本位置计算，支持中文和空格；产物缺失时显示对应构建命令，不静默启动旧 EXE。
5. 生命周期脚本跟随构建选择，继续核对路径、PID 和窗口身份，不仅凭进程名操作。
6. 构建 debug 和 release 独立程序。release 命令为 `npm.cmd run tauri -- build --no-bundle`，安装包留到 P3。

| 编号     | 操作                       | 预期                                             |
| -------- | -------------------------- | ------------------------------------------------ |
| START-01 | 资源管理器双击 debug EXE   | 应用出现，无可见伴生控制台                       |
| START-02 | 双击 release EXE           | 同上，不依赖 Node/Vite 开发服务器                |

### P1.2 关闭隐藏与闲置回归

移除 close-handler 锁定已经完成，重点是验证行为和修复回归。

- 保留窗口/WebView 实例，关闭只 hide。不用保存主密码、持久化解锁密钥、重挂载 VaultRoot 解决恢复问题。
- Rust 是会话状态与权限来源。不通过忽略 IPC 锁定错误或删除初始化保护来避免密码提示。
- 未到期的恢复可以成为新活动；到期后先确认锁定，不能用恢复事件续期已超时会话。
- 检查监听注册与清理、React StrictMode、异步认证 epoch、文件对话框与锁定交互。
- 使用隔离测试账号与数据目录。若需隔离目录入口，仅作为明确的开发/测试选项，默认数据路径和生产权限保持不变，不加绕过主密码的调试命令。

| 编号       | 前置与操作                                     | 预期                                   |
| ---------- | ---------------------------------------------- | -------------------------------------- |
| SESSION-01 | 解锁、关闭闲置锁定；点 X → 托盘恢复，重复 3 次 | 同一会话保留，记录可访问，不要求主密码 |
| SESSION-02 | 设 1 分钟闲置；隐藏后到期前恢复                | 保持解锁                               |
| SESSION-03 | 设 1 分钟闲置；隐藏超过期限再恢复              | 解锁页，后台拒绝读取/复制密码          |
| SESSION-04 | 前台闲置到期                                   | 锁定，敏感展示移除                     |
| SESSION-05 | 分别从侧栏、轮盘、托盘锁定                     | Rust 状态锁定，恢复需密码              |
| SESSION-06 | 完全退出并重启                                 | 需要主密码，已有库与记录完好           |
| SESSION-07 | 隐藏时重复启动同一构建                         | 原实例恢复，未到期会话保留             |
| SESSION-08 | 解锁/改密/导入过程中发生锁定                   | 迟到结果不重开会话、不误提交           |

P1 交付：相关测试通过，补针对状态回归的测试；不用“源码没有某字符串”代替运行验收。逐个记录原生用例结果和未执行编号。

## 最终验收交付格式

更新阶段状态，填写 docs/acceptance-report.md。不要让用户重新描述需求，也不要把所有任务直接标为完成。

建议报告结构：

```markdown
# 本轮实施与验收记录

## 范围与基线

日期、环境/工具链、工作区、提交号或无 Git 基线、完成阶段。

## 变更清单

文件 | 改动目的 | 涉及的数据/会话边界。

## 自动检查

命令 | 日期 | 退出码 | 数量/结果 | 未执行原因。

## 原生检查

用例编号 | 构建类型 | 操作和实际结果 | 通过/失败/未执行。

## 已修复问题

复现、原因、最小修复、验证证据。

## 剩余问题

严重程度、复现步骤、影响、建议下一步。

## 构建产物

实际路径、构建时间、类型、是否安装/签名/实测。

## 交给最终验收者

重点文件、未覆盖边界、与计划不同的决定及理由。
```

原模型最终复核：控制台是否真正解决；关闭/恢复/超时正确；锁定后异步不能恢复权限；导入/恢复/改密不丢数据；真实库未被测试影响；CSP/窗口权限没扩大；QQ 和系统锁屏联动未回流；测试报告与真实证据一致。
