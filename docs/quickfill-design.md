# 普通应用剪贴板连续填写设计

当前产品只支持“允许复制粘贴”的普通应用，不做应用控件适配，不使用 UI Automation、SendInput 或自动提交。QQ、微信等受保护输入框明确排除。

## 用户流程

1. 用户在目标应用打开登录页，并点击用户名输入框或准备点击。
2. 呼出酸橙悬浮轮盘，点击“寻找账号”。搜索和账号列表留在悬浮窗，不打开主收藏室。
3. 点击账号后选择“连续填写账号”。工具立即把用户名写入剪贴板，显示 20 秒等待状态。
4. 用户回到目标应用点击用户名框，按 `Ctrl + V`，再按一次 `Tab`。
5. 工具只在这次流程中检测一次 Tab，验证会话仍有效后把密码写入剪贴板。
6. 用户按 `Ctrl + V`。流程结束，等待状态取消；不会自动输入、自动按 Tab、自动提交或继续监听。

普通复制模式仍可单独复制用户名或密码。连续模式比打开主窗口、重复搜索和第二次选择账号更短，但用户仍明确控制目标输入框和两次粘贴。

## 监听边界

Tab 监听不是常驻监听：只有用户点击“连续填写账号”后才启动，最长 20 秒，只消费一次 Tab；Esc、锁定、主密码会话变化、账号删除或超时都会取消。没有选择连续模式时不读取全局按键。实现使用 Windows 的短时按键状态检查，不注入键盘事件，不读取用户输入内容，不记录按键。

Tab 本身无法证明用户已经完成第一次粘贴，因此工具不把 Tab 当成安全认证；密码切换后仍由用户决定是否粘贴。若用户在 20 秒内没有按 Tab，流程结束且原有剪贴板清理规则继续生效。用户在此期间复制其他内容时，工具不得覆盖或清空新内容。

## 权限与数据边界

悬浮窗只获得三个最小命令：读取已解锁库的账号元数据、启动连续复制、取消连续复制。密码只在 Rust 后端收到一次 Tab 后读取，不发送到悬浮窗；前端只显示账号名、用户名和状态。锁定或闲置到期会推进会话 epoch，迟到的 Tab 不能读取密码。

目标应用由用户自己点击和确认，不根据窗口标题、进程名或图标做适配。该方案适用于能正常接受用户 `Ctrl + V` 的输入框，不声称支持安全输入控件、管理员窗口或防粘贴应用。

## 测试要求

- Rust：20 秒超时、Tab 只触发一次、Esc/取消、锁定 epoch、账号不存在、复制失败和用户改写剪贴板后的处理。
- React：悬浮窗搜索不导航主窗口；选择账号显示连续状态；状态事件后结束等待；错误和取消可恢复。
- 原生人工：用记事本和用户自己的测试账号验证用户名粘贴、Tab 后密码粘贴；不要在 QQ、微信或历史蓝屏环境中测试；不使用真实生产密码作为测试数据。

该功能是剪贴板辅助，不是跨应用自动填写器。兼容性应按“用户实际能否粘贴”逐个记录，不把应用名称列为已支持证明。
