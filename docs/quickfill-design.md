# C0 单项填写设计

本轮仅设计与 scripts/quickfill-model.mjs 纯模型，不接入产品、不读真实应用、不访问剪贴板或账号，不注册监听，不包含 SendInput/UIA 实现。

空闲 → 捕获目标 → 搜索选择 → 准备 → 目标复核 → 执行/取消。每个请求仅选择用户名或密码一个字段；不发 Tab、回车或组合序列。模型 captured 状态代表搜索选择阶段，executed 仅表示假目标验证成功。

请求绑定 Rust 会话 epoch、短期票据（建议 5 秒）、进程生命周期、窗口与焦点标记；任何标记变化、到期、锁定、Esc、权限不支持均取消。终态不可重用。未来票据由后端生成、单次消费，不能信任前端提供的 epoch 或目标身份。复核到实际输入仍存在竞态，C1 必须研究并验证取消策略，模型不证明消除了此竞态。

main 继续独占密码库命令。轮盘只导航；未来快捷面板需独立最小 capability 与后端鉴权，不复制 main 权限，不返回整个密码库。只有执行阶段才取选定字段，失败立即释放。普通权限限定，不能核验则取消，不提权。

HWND、标题、PID 单独不可靠，PID/句柄可复用。结合进程启动身份、窗口生命周期和焦点变化仍不能识别所有应用内部字段或保证防钓鱼。模型的 mock token 不代表 Windows 身份验证实现。

测试覆盖目标各标记变化、锁定 epoch、期限、权限、重复请求和取消。C1 必须先在隔离环境自建目标测试，再讨论 Edge/Chrome/Steam 等应用；QQ 保护输入框排除，旧原型暂停。

## 2026-09-20 用户指定 Steam 的新增实现

上文 C0 是历史范围。本轮用户明确要求普通应用填写并指定 Steam，新增独立 `src-tauri/src/steam_fill.rs`，不恢复 `crates/windows-validation`、QQ 或旧 UIA 探测流程。

流程：在已验证收藏室选择记录 → 点击“准备填写用户名”或“准备填写密码” → 30 秒内切换 Steam 并点击对应框 → 按 Ctrl+Alt+P 并松开。只在准备后临时注册该快捷键；注册失败明确报占用，结束释放。Esc、按钮取消、手动/闲置锁定、30 秒过期均取消。请求只保留 ID/字段/epoch，不缓存密码。

热键触发时记录当前前台窗口、焦点 HWND、线程和 PID，持有进程句柄避免仅凭复用 PID 判断身份；只接受 steam.exe/steamwebhelper.exe 名称，拒绝管理员进程或查询失败。等热键松开再复核窗口/焦点/进程存活、会话 epoch，取单一字段写入已有所有权剪贴板服务，核对序号，发送单次 Ctrl+V。无 Tab/回车/自动登录，不提升权限、不操作驱动、不注册全局键盘钩子。

这是显式快捷粘贴：Windows 焦点检查不能识别 Steam 的 CEF 内部账号/密码字段，也不能消除检查后焦点变化竞态；进程名允许列表不是数字签名认证，不能抵御同一用户恶意伪装进程。必须由用户点击正确输入框；有内容时可能按 Steam 行为插入或替换选区。与手动复制相同经过剪贴板，30 秒仅清除仍归本次复制的内容，第三方历史不受控。SendInput 返回只证明 Windows 接受事件，不证明 Steam 已收值。

本轮编译及无输入副作用的权限/epoch测试可执行；受历史蓝屏事件约束，不在当前日常环境自动运行 SendInput/Steam 原生测试。真实 Steam 版本与字段接收仍待隔离环境实测，因此 UI 标“试用”，不能声称兼容已验收。
