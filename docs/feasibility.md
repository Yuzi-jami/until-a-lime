# 可行性验证与阶段计划

> 当前阶段以 [plan.md](plan.md) 为准。本地加密库 B1 已接入，见 [vault.md](vault.md)。以下包含旧设计与历史验证状态；演示数据、UI 锁定等旧描述仅适用于早期版本或浏览器预览。

## 阶段 0：验证（当前）

路线已调整：以下逐应用登录页和浏览器桥接计划保留为后续增强。第一版的技术验证以 [通用快捷填写原型](quickfill-prototype.md) 为准：全局热键、搜索、焦点恢复、单项输入与可选 Tab 连续输入。QQ 未暴露密码框不再阻塞第一版。

1. 记录开发环境与目标客户端版本。
2. 使用只读脚本检查 UI Automation 控件能力。
3. 在自行创建的测试登录窗口中，以虚构凭据验证 Rust 识别与填写，以及焦点切换时取消行为。
4. 在目标客户端真实登录页中，由用户触发虚构凭据填写，不提交登录；记录成功率与失败条件。
5. 验证 Chromium 扩展与 Native Messaging 桥接，仅使用测试页面和虚构数据。

完成标准：浏览器通信可用，至少一个桌面客户端登录页可可靠识别和填写；目标变化时拒绝填写。完成之前不承诺软件兼容性，也不存放真实凭据。

## 兼容性矩阵

QQ 登录页补充验证（2026-09-10）：用户打开登录页后已找到顶层窗口，版本 9.9.27.45758，腾讯数字签名有效。Rust 枚举发现一个可用非密码 Edit，但没有可用密码 Edit；PowerShell 多次采样返回更少或没有 Edit。接口枚举不一致，不代表界面实际只有一个输入框。向顶层窗口和渲染子窗口请求标准 MSAA 对象后，仍未获得可靠密码字段。

未重启 QQ、未调整启动参数、未填写或提交 QQ 登录信息。后续评估用户手动定位加快捷键辅助填写，或版本专用的辅助功能接入，两条路线均尚未实测通过。原始能力报告见 [QQ 探测记录](qq-login-probe-2026-09-10.json)。

| 目标 | 方案 | 当前结论 |
| --- | --- | --- |
| Edge / Chrome | Chromium 扩展 + Native Messaging | 架构可行，本项目尚未实测 |
| Steam | UI Automation，必要时应用专用回退 | 待登录页验证；Steam Guard 不属于密码填写 |

只读探测脚本不会读取 Name、Value、窗口标题或聊天文本。它仅输出进程版本、窗口数量、控件数量和模式支持统计。其结果不能证明当前窗口是登录页，也不能证明密码框可写；辅助功能可能不开放、延迟响应或受到权限限制。
