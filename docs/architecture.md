# 技术架构草案

> 当前阶段以 [plan.md](plan.md) 为准。本地加密库 B1 已接入，见 [vault.md](vault.md)。以下包含旧设计与历史验证状态；演示数据、UI 锁定等旧描述仅适用于早期版本或浏览器预览。

状态：已选择 Rust + Tauri 2；以下接口边界待技术验证后定稿。

2026-09-10 路线调整：第一版以通用快捷填写为核心。用户手动点击输入框，再搜索记录选择填写项；不依赖 QQ 等应用暴露密码控件。下文的应用适配、浏览器扩展与网站自动匹配属于后续增强。原型说明见 [快捷填写验证](quickfill-prototype.md)。

## 用户操作流程

点击目标输入框 → 按全局快捷键 → 解锁（如已锁定）→ 搜索账号 → 选择用户名、密码或连续填写 → 恢复并核验原目标 → 填写。默认不自动提交登录。

首次使用包括创建本地密码库、设置主密码和手动添加账号。浏览器自动保存新凭据在基础填写稳定后实现；桌面端不采用全局键盘监听来捕获密码。

## 模块边界

| 模块                 | 职责                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| Web 前端             | 账号列表、搜索、编辑、设置、快捷面板；不直接访问数据库或系统填写接口 |
| Tauri 命令层         | 提供最小权限命令，检查锁定状态、参数与调用窗口权限                   |
| Rust 密码核心        | 加解密、密码生成、锁定状态、记录管理、格式版本与迁移                 |
| Windows 平台层       | 热键、窗口识别、UI Automation、填写前目标复核                        |
| 应用适配层           | 按应用与版本确定控件选择规则、支持状态与回退方式                     |
| 浏览器扩展与本地桥接 | 使用 Native Messaging；校验扩展来源，并处理域名、页面和填写请求      |

前端不一次性获取完整解密密码库。列表只返回必要的元数据；显示、编辑或填写密码属于单独的敏感操作。前端编辑密码时仍会接触明文，不能声称明文永远不离开 Rust。

## 密码存储方向

- 主密码通过 Argon2id 派生密钥，使用随机盐；参数通过目标机器性能测试确定。
- 使用成熟库提供的认证加密，例如 XChaCha20-Poly1305；每次加密生成新 nonce，不自行实现密码算法。
- 第一版优先评估带版本的整体加密文件，用户名、域名、备注等也在加密范围内；头部仅保留必要的格式、KDF 参数和加密信息。
- 限制可接受的文件大小与 KDF 参数，避免异常文件导致资源耗尽。
- 原子替换写入、明确失败恢复流程、加密备份；不落盘明文临时文件。
- 锁定时释放解密数据并尽可能清零敏感缓冲区；应用内手动、退出及闲置时锁定，关闭窗口只隐藏到托盘；系统锁屏/休眠联动按用户要求不接入。不能保证清除操作系统及所有依赖中的明文副本。
- 主密码不保存，忘记后第一版无服务器恢复能力。Windows Hello 延后单独设计。

## 填写与通信边界

浏览器按 origin 与明确的域名匹配规则推荐账号，不能简单使用字符串包含关系。跨域 iframe、HTTP 页面和页面跳转需单独定义策略。Native Messaging 仅允许指定扩展连接，不使用无鉴权本地 HTTP 服务。

桌面应用不能仅凭窗口标题或图标认定身份。结合进程路径、签名信息、进程启动身份与控件归属判断；这些检查不能防御已控制用户系统的恶意软件。

快捷面板会改变前台窗口，因此调用时记录原始目标，选择后重新确认窗口、进程与控件归属。目标改变、窗口失效或控件不确定时取消填写。

第一版采用用户明确触发的模拟输入；UI Automation 作为可选增强。需要验证键盘布局、Unicode、焦点变化和权限边界。原生焦点不能识别所有应用内部的字段变化，因此不声称能够自动核实密码框或防止钓鱼。ValuePattern 的存在也不能直接作为可填写证明。

不自动提升整个密码管理器的权限。管理员应用和安全桌面不纳入初期支持范围。剪贴板回退延后，因为历史记录或其他进程可能保留内容。

## 发布前的必要验证

密码库：错误主密码、篡改、截断、随机性、损坏恢复、写入失败、格式迁移。

填写：多账号、目标切换、窗口关闭、错误进程、锁定后请求、浏览器跨域与导航变化。

工程：固定依赖版本、格式检查、静态检查、核心测试、Windows 构建与安装验证、依赖许可证与安全公告检查。代码签名在公开分发前评估。
