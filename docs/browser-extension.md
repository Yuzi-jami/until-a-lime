# Edge / Chrome 扩展（本地预览版）

2026-09-30，扩展 0.2.0。Manifest V3 + Native Messaging，本机密码库。首次加载或新增权限仍由浏览器确认；后续自动显示登录建议，不必每次打开工具栏。尚未商店发布。

## 使用

1. 启动新版酸橙。在收藏室设置/浏览器插件页点击一次“准备浏览器扩展”，向当前用户 HKCU 注册 `dev.untilalime.browser`（Chrome、Edge），显示扩展文件夹路径。不提权，不修改浏览器策略。已启用的连接会自动恢复，桌面启动时会同步新版扩展文件和 host 路径，无需反复准备。
2. 打开 `edge://extensions` 或 `chrome://extensions`，打开开发者模式，选择“加载解压缩的扩展”，选择提示的 `extension` 文件夹。浏览器确认不可省略。商店版需要所有者后续提交、审核与正式安装链接，本轮不公开发布。
3. 从旧版升级到 0.2.0 时在扩展管理页重新加载一次，允许 HTTPS 网站访问权限，并刷新已打开的页面。之后新页面自动生效。在收藏室验证一次主密码；重启进程或密码库锁定后仍需验证，不保存主密码或解密密钥到磁盘。
4. 点击 HTTPS 页面登录输入框，酸橙建议自动出现，选择账号后填写，不自动提交。工具栏图标和 **Alt + Shift + L** 仍可使用。支持 HTTPS iframe 内的登录框；工具栏会选择唯一可识别表单，或优先选中上次聚焦的表单。页面有多个无法区分的登录框时，直接在目标输入框使用建议。
5. 关闭连接可点击“断开浏览器连接”，立即拒绝新请求并清除启用偏好；如需移除扩展，到浏览器扩展管理页操作。断开不会删除用户密码库，保留安装注册供重新连接。

已启用连接时，Native Messaging host 在找不到运行中的酸橙时会后台启动程序并短暂重试，不弹主窗口、不自动解锁。主动断开后不会自行重启连接。首次安装仍不能省略浏览器加载动作。

账号匹配支持同一注册域下的子域名，如 `passport2.chaoxing.com` 与 `v1.chaoxing.com`；使用包含私有后缀的 PSL，不把不同 `github.io` 租户、不同 `co.uk`/`com.cn` 网站混为同站。旧 HTTP 记录可用于同站 HTTPS 页面，但绝不向 HTTP 页面填写；自定义端口要求一致，跨子域不放宽自定义端口。列表显示保存的网站来源，密码只在用户选中后读取。

只有一个可见密码框且用户名框可唯一识别才填写，手机号/用户名提示优先于搜索/验证码等无关字段。注册/改密标记、跨域表单 action、HTTP、内部页、已有不同用户名或已有密码、目标变更、10 秒过期仍拒绝。多步登录、Shadow DOM 和复杂网站可能需要手动复制。不会访问浏览器密码数据库或导出浏览记录。

## 权限与通信

扩展使用 activeTab、scripting、nativeMessaging，以及 `https://*/*` 主机权限，在 HTTPS 页面及子框架中监听登录框聚焦。没有密码持久缓存，不读取输入框中的密码，也不通过网页 postMessage 接受操作。聚焦只请求账号元数据；选中账号后由后台验证扩展发送者、HTTPS 来源、活动标签及 documentId，再准备表单、取出所选密码并交给同一文档。密码不返回给账号建议脚本。

本机 host 只接受固定扩展 ID 来源，以长度前缀 stdio 接入；转发至 127.0.0.1 随机端口，使用每次应用启动新生成的 256 位 token。无 HTTP/CORS 服务。请求上限 256 KiB，连接读写有时限。后端再次检查 Rust 会话、闲置截止时间、操作类型和上述网站匹配规则；列表没有密码，显式 fill 只返回所选账号。锁定后不接受后续读取，不能撤回已传入网页的密码。

连接配置通常在 `%APPDATA%\dev.untilalime.desktop\browser-bridge.json`，依赖当前用户目录 ACL；没有保存主密码/解密密钥。同一 Windows 用户下的恶意进程可读取连接 token，这不是防御已被控制的本机用户会话；固定扩展 ID 也不是对本地恶意进程的身份认证。CSV/IPC/网页运行时副本无法保证完全擦除。密码提交给网页后该网页脚本可以读取它，这是填表本身的权限边界。

## 构建

`npm.cmd run browser:prepare` 构建 host；Tauri 会将同一 Cargo 包的额外二进制随安装包分发。`npm.cmd run tauri -- build` 自动运行前端构建和 host 准备，NSIS 包含 `lime-browser-host.exe`。开发检查可直接运行 `cargo test -p until-a-lime --locked`，或运行 `scripts/Check-Desktop.ps1`。不要使用旧安装包测试新扩展。

manifest 的公钥固定开发扩展 ID，不含私钥；商店发行的 ID 若不同，需更新 manifest、host 来源白名单及配置，并重新构建。当前运行链路与 DOM 模型有测试，但 Edge/Chrome 安装、权限提示、真实网站登录尚待实测，见验收报告。

## xcpcai.com 与快捷键

2026-09-20 已只读检查 `https://xcpcai.com/`：先点页面 **Sign in**，会出现登录弹窗，包含 name=username 的文本框和 name=password 的密码框；两个字段同属本站 form。检查时未登录、未读取或输入用户凭据。

Tab 仅切换输入框，不触发扩展。正确顺序：酸橙收藏室验证 → 站点打开 Sign in 弹窗 → Alt + Shift + L（或工具栏酸橙图标）→ 选择账号。记录网址填写 `https://xcpcai.com`。快捷键被占用可在 `chrome://extensions/shortcuts` 或 `edge://extensions/shortcuts` 中修改。

旧版 0.1.1 的更新步骤由上面的 0.2.0 流程替代。今后桌面启动自动同步已启用的扩展文件；开发版代码升级时仍可能需要在浏览器重新加载一次。

表单填写现在逐个设置并通知 React，避免用户名更新时把密码恢复为空；若重绘更换了密码框则取消，防止继续向失效目标传值。xcpcai 的实际表单属性已核查，相应 DOM/受控重绘模型通过测试仍不等于真实账户登录验证。

2026-09-30 对超星公开登录页做了只读 HTTP 检查：v1 顶层使用 iframe 指向 passport2，内部表单 action 为空，用户名框 id=phone，密码框 id=pwd，夹有隐藏字段。未访问个人密码库或填写真实凭据。相应表单模型、iframe 文档选择和同站授权均有回归测试；实际账号填写仍待用户验证。
